# Docent

An AI writes 2,000 lines. Your name goes on the pull request. You have not read
a line of it, and the reviewer is about to ask you questions.

This plays the walkthrough. The editor opens each file, scrolls to the lines
being discussed, dims everything else, and **reads the explanation out loud
while you look at the code**.

```
 ◀  Pause  ▶   1x ▾   🔊                      14 of 22  ·  ~18 min left

 hid.go      report.go   keys  payload  session.go              tests
 ▓▓ ▓▓ ▓▓ ▓▓  ▓▓ ▓▓ ▓▓    ▓▓   ▓▓ ▓▓    ▓▓ ▓▓ ▓▓ ██ ░░ ░░ ░░ ░░  ░░ ░░ ░░ ░░
                    ▔▔                     ▔▔

 teardownStream: the ordering that deadlocks if reversed
 ios/hid/session.go:439

 The receiver is closed before the drain is waited on. Reverse
 those two lines and it hangs forever, because closing the socket
 is the only thing that ends a blocked read.

 READ   closing the receiver unblocks the drain
        the comment and the ordering at session.go:461
```

The bar is a map of the change: one segment per step, grouped under the file it
belongs to, each file as wide as the number of steps it earned. Mechanical
steps are dimmer, so you can see at a glance which file is a formality and
which is where the thinking is. A segment underlined in amber rests on claims
nobody verified, which is where a reviewer should push.

## A tour travels with the branch

A tour is a `.docent/tour.json` file committed to the repo, so anyone who
checks out the branch plays the same walkthrough, at their own speed, stopping
wherever they like.

That is the point. A reading order in a pull request comment is a list of links
someone skims. A tour is the review, handed over.

## Getting a tour to play

This extension is the player. Tours are generated by the
[docent plugin for Claude Code](https://github.com/sakhisheikh/docent), which
reads the diff, sorts the decisions from the plumbing, and writes the tour with
every claim marked as tested, executed, read, or merely inferred.

In Claude Code:

```
/plugin marketplace add sakhisheikh/docent
/plugin install docent@docent
```

Then, on the branch you are about to send for review, `/docent`.

You do not need the plugin to review someone else's change. If the branch
already carries a tour, this extension will offer to play it when you open the
folder.

## Using it

Press **⇧⌘P** on macOS, or **Ctrl+Shift+P** elsewhere, and run
**Docent: open the tour**. There is also a `docent` item in the status bar
which plays and pauses.

Everything is buttons in the panel, so the keys are optional. macOS reserves
**⌘⌥Space** for Finder search, which is why these use Control and Option. On a
Mac keyboard **⌥** is the Option key, sometimes printed as Alt.

| macOS | Windows and Linux | |
|---|---|---|
| **⌃⌥Space** | Ctrl+Alt+Space | play or pause |
| **⌃⌥[** and **⌃⌥]** | Ctrl+Alt+[ and ] | previous, next |
| **⌃⌥-** and **⌃⌥=** | Ctrl+Alt+- and = | slower, faster |
| **⌃⌥V** | Ctrl+Alt+V | voice on or off |

Every field in the panel is editable. The pencil next to a title, a narration,
a claim or its evidence opens an inline editor and saves straight back to
`tour.json`, so a tour can be corrected while it plays.

## Speech

Each stop's title and narration are read out loud, and the step ends when the
sentence does rather than on a guess at how fast you read. The speaker button
silences it.

| setting | |
|---|---|
| `docent.speak` | read stops out loud, on by default |
| `docent.voice` | which system voice, empty for the default. macOS only; `say -v '?'` lists them |

macOS uses `say`, Linux uses `spd-say` and needs `speech-dispatcher`
installed. Windows has no voice yet and holds each step on a timer instead.

## Line numbers that moved

Each step carries an `anchor`, a snippet of the code it points at. When the
file has changed since the tour was written, the player searches outward from
the recorded line, finds the anchor, and shifts the highlight to follow it.

When it cannot find the anchor at all it says so in the panel rather than
jumping somewhere arbitrary. The narration is still right; the highlight may
not be.

## What is proven and what is not

The project grades its own claims, so this page does too.

- **The player works.** Tours play, seek, spotlight, follow drifting line
  numbers, read out loud, and save edits back to `tour.json`. Covered by tests
  and used daily.
- **A tour generated end to end by the plugin has not been proven.** Every tour
  played so far was written by hand. That is the open question, and the
  [contributing guide](https://github.com/sakhisheikh/docent/blob/main/CONTRIBUTING.md)
  says what would help.
